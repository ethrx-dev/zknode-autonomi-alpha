# zknode-autonomi — Mixnet Integration

## Integration Architecture

```
ant-node ──SOCKS5──▶ mixnet-proxy ──SURB──▶ 3-hop mixnet ──▶ Autonomi peers
                        │
                   300 lines Go
                   no Autonomi changes
```

The `mixnet-proxy` is the only custom component. It bridges ant-node's traffic into the Katzenpost mixnet as a transparent SOCKS5 proxy.

## Mixnet Topology

| Component | Count | Config | Role |
|-----------|-------|--------|------|
| Directory Authority | 3 | auth1-3/authority.toml | PKI consensus, node discovery |
| Mix Node | 3 | mix1-3/katzenpost.toml | 3-hop onion routing (layers) |
| Gateway | 1 | gateway1/katzenpost.toml | Client ingress, SURB management |
| Service Node | 1 | servicenode1/katzenpost.toml | Mixnet exit, packet forwarding |
| SOCKS5 Proxy | 1 | config/proxy/config.json | Transparent bridge |

**Network**: All mixnet containers use `network_mode: host` — they share the host's network namespace and communicate via `127.0.0.1`. This is the configuration genconfig was designed for and avoids complex address mapping.

**Cryptography**: Post-quantum Sphinx packets with ML-KEM-768 (wire protocol) and x25519 (NIKE for onion routing). PKI uses Ed25519 signatures.

## Config Generation

Configs are generated by the built-in `genconfig` tool from katzenpost v0.0.73-rc3:

```bash
genconfig \
  --voting --wirekem MLKEM768 --nike x25519 \
  --baseDir /var/lib/katzenpost --outDir /out \
  --layers 3 --nodes 3 --gateways 1 --serviceNodes 1 \
  --nrVoting 3 --noMetrics --logLevel DEBUG
```

This generates:
- Authority configs with SphinxGeometry, PKI keys, and voting parameters
- Server configs for mix/gateway/service nodes
- Client configs (thin client + full client)
- Docker Compose reference

All PKI key files are gitignored — regenerated per deployment for security.

## Dirauth Consensus

The 3 directory authorities use threshold voting to publish PKI documents. All 3 must be running to reach consensus. The PoC uses an internal retry loop:

```yaml
entrypoint: ["sh", "-c"]
command: ["while true; do /usr/local/bin/dirauth -f ...; sleep 2; done"]
```

This ensures dirauths automatically retry until all three are up and consensus forms. In production, systemd or a supervisor would handle this.

## Three Integration Models

### Model A: Reference Integration (PoC — Current)

ZKNetwork publishes the mixnet-proxy as open-source. Autonomi documents it as a recommended add-on for privacy-conscious operators.

- **ZKNetwork provides**: mixnet-proxy code, Docker images, configs
- **Autonomi provides**: Documentation links, community support
- **Timeline**: Working now (PoC)
- **Autonomi changes**: None

### Model B: Bundled Distribution

The mixnet is bundled with the `ant` CLI as `ant node start --private`.

- **ZKNetwork provides**: Embedded proxy library, mixnet image maintenance
- **Autonomi provides**: `--private` flag in ant CLI
- **Timeline**: 1-2 months
- **Autonomi changes**: CLI flag, image packaging

### Model C: Deep Integration

The mixnet becomes a built-in transport in `saorsa-transport`.

- **ZKNetwork provides**: Sphinx library for saorsa-core
- **Autonomi provides**: Mixnet transport trait
- **Timeline**: 3-6 months
- **Autonomi changes**: Core networking, peer protocol

## SOCKS5 Proxy Design

The mixnet-proxy is a simple SOCKS5 server (~300 lines of Go):

```go
// 1. Accept SOCKS5 connection from ant-node
// 2. Parse target address from SOCKS5 request
// 3. Dial mixnet gateway with target address
// 4. Bidirectional pipe between client and gateway
```

Key features:
- SOCKS5 CONNECT only (no UDP ASSOCIATE, no BIND)
- Connects to mixnet gateway at 127.0.0.1:30004
- Management API on port 9090 (JSON status, health check)
- Zero Autonomi code changes required

## Mixnet Proxy Architecture (Current)

The SOCKS5 proxy uses the **official Katzenpost thin client library** compiled into the Go binary. It connects to `kpclientd` (the Katzenpost client daemon) on `127.0.0.1:64332`, which handles all mixnet communication: Sphinx packet creation, SURB reply management, PKI document retrieval, and gateway connection maintenance.

```
ant-node ──SOCKS5──▶ mixnet-proxy ──thin──▶ kpclientd ──▶ gateway ──▶ mix-3/2/1 ──▶ servicenode
  :12000               :1080              :64332            :30004
```

### Key enhancements over original design:
- **Thin client library**: Official `client/thin` Go import (no raw TCP to gateway)
- **Post-quantum hash**: BLAKE2b-256 (matches hpqc library)
- **PKI document parsing**: Extracts services from ServiceNodes
- **SURB reply handling**: Echo test confirmed 3.2s roundtrip (100% success)
- **ZK proof endpoints**: Bandwidth, storage challenge, and prove proxied through mixnet
